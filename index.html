💳 Cobro con terminal (tarjeta)

NovaPOS no procesa pagos con tarjeta por sí mismo: esto requiere una cuenta de comercio con un procesador (Conekta, Stripe o Square) y, en la mayoría de los casos, su propia terminal física certificada.

📋 Cómo se conecta (guía general)
1. Da de alta un contrato de comercio con Conekta, Stripe o Square (piden RFC y datos fiscales del negocio).
2. Cada procesador certifica su propia terminal física o modalidad "tap to pay" — no es un botón que se agregue a cualquier página.
3. Las llaves secretas del procesador nunca deben ir en este archivo HTML/JS — cualquiera con el código fuente podría verlas y usarlas. Deben manejarse desde un servidor propio.
4. Esto implica agregar un backend al proyecto (NovaPOS hoy usa Google Sheets, que no es apto para procesar cobros con tarjeta).
5. Es un proyecto de desarrollo aparte, no una casilla que se activa aquí — si te interesa, contáctanos para cotizarlo a detalle.

🔗 Google Sheets — Base de datos
⚪ Sin configurar — los datos se guardan localmente

Sin esta clave, cualquiera que descubra la URL del Apps Script podría leer o borrar los datos del negocio. Debe coincidir exactamente con SYNC_SECRET en el script (ver instrucciones abajo).

⬇ trae lo que haya en la nube a este dispositivo (lo reemplaza aquí). ⬆ hace lo contrario: sube lo de este dispositivo y reemplaza lo que había en la nube. Úsalos según de qué lado está la información más reciente — nunca combinan ambos lados automáticamente. Para ahorrar datos móviles, las sincronizaciones normales solo traen ventas de los últimos 90 días — usa "📜 Cargar historial completo" (consume más datos) si necesitas ver/reportar ventas más viejas.

📋 Instrucciones de configuración
1. Ve a sheets.google.com → crea una hoja nueva.
2. Ve a Extensiones → Apps Script → pega el código del backend.
3. Reemplaza SYNC_SECRET al inicio del script por la misma clave que pongas arriba, y guarda.
4. Implementa como Aplicación Web → Cualquier persona → copia la URL.
5. Pégala arriba junto con la clave y guarda.

📱 Recargas telefónicas

NovaPOS no se conecta directo a Telcel/AT&T/Movistar: eso lo hace un mayorista con webservice propio (ej. Seycel, Taecel, Sivetel). Para no exponer las credenciales de ese proveedor en este archivo HTML/JS —visible para cualquiera con el código fuente—, la recarga se manda al mismo Apps Script de arriba (usa la misma URL y clave secreta) y es ahí, del lado del servidor, donde se agrega la llamada real al proveedor.

En modo manual, NovaPOS no intenta llamar a ningún proveedor: guarda el detalle (compañía, número, modalidad, comisión) y genera el ticket de inmediato, para negocios que ya cobran y recargan directo en su terminal de pago.

⚪ Sin conexión a Google Sheets — las recargas solo quedarán en el historial local

Se usa únicamente para estimar tu ganancia en el tablero de Recargas — no cambia lo que le cobras al cliente ni lo que paga el proveedor.

Se suma al monto de la recarga en el cobro y se desglosa en el resumen y en el ticket.

📋 Modalidades y teléfono de soporte por compañía
Cada compañía puede ofrecer varias modalidades de recarga (tiempo aire, paquete de datos, amigo sin límites, etc.) — agrégalas aquí según el catálogo que te dé tu proveedor. El teléfono de soporte es opcional y aparece en el ticket solo si lo llenas.
📋 Cómo conectar tu proveedor real
1. Da de alta una cuenta de distribuidor con tu proveedor de recargas (Seycel, Taecel, Sivetel, etc.) y obtén sus credenciales de API.
2. En el código Apps Script (botón "Copiar código Apps Script" en la tarjeta de arriba), busca la función sendRecharge_ — ahí hay un TODO marcado para pegar la llamada real a tu proveedor con UrlFetchApp, usando las credenciales guardadas en Script Properties (nunca en este HTML).
3. Vuelve a implementar el Apps Script como Aplicación Web para que tome el cambio.
4. Prueba con una recarga pequeña desde la pantalla de Recargas antes de operar con clientes.
🧑‍💼 Vendedores

Da de alta a las personas que van a abrir caja, cada quien con su propio NIP y su código de empleado (el mismo que uses en tu otro sistema de nómina/bonos — el resumen de turno lo incluye en su código QR). Al abrir turno, cada vendedor ingresa su NIP (no se elige de una lista) — así queda registrado quién abrió/cerró realmente, y eso se pega a cada venta, al corte de caja del cierre y al ticket impreso. Si no das de alta a nadie, la caja se abre igual que antes, sin pedir NIP.

🕐 Turnos de personal

Define los turnos de tu negocio (nombre y horario) y qué empleados trabajan cada uno — es informativo, para llevar el rol de personal; no reemplaza la apertura/cierre de caja de cada quien, que sigue siendo libre.

🔐 Acceso a Configuración

Si lo configuras, esta pantalla de Configuración (incluida esta misma tarjeta) va a pedir este NIP cada vez que alguien intente entrar — solo el dueño debería conocerlo. Déjalo vacío para que Configuración quede abierta como hasta ahora.

🕐 Ventas anteriores

Para capturar después una venta que sí se realizó pero no se alcanzó a registrar en su momento (falla del dispositivo, etc.), con su fecha/hora real para que cuente en el turno correcto. Al estar en Configuración, queda fuera del alcance de los empleados si le pusiste NIP del dueño arriba.

📋 Resumen de turno

Cada vez que se cierra la caja, se abre automáticamente para imprimir un resumen del turno (ventas, ingresos/egresos, saldo). Si pones un correo aquí, además se lo envía por email — déjalo vacío para que solo se imprima, como hasta ahora.

💳 Mercado Pago (terminal Point)

Para cobrar con tu terminal física Point desde el modal de Cobrar. El Device ID es propio de este dispositivo — si tienes varias tablets, cada una puede tener su propia terminal pareada, así que esto no se sincroniza entre dispositivos, a diferencia del resto de la configuración.

⚪ Sin buscar todavía
📋 Cómo configurar el Access Token
1. El Access Token de Mercado Pago nunca se captura en NovaPOS ni viaja a la hoja de cálculo — se guarda directo en tu Apps Script para que nadie más lo vea.
2. En tu proyecto de Apps Script → ⚙️ Configuración del proyecto → Propiedades del script → agrega la propiedad MP_ACCESS_TOKEN con tu Access Token de producción.
3. No hace falta volver a implementar el script para que tome una propiedad nueva.
4. Da clic en "🔍 Buscar terminal" para confirmar que la conexión funciona y copiar el Device ID correcto.
5. Prueba con un cobro pequeño antes de usarlo con clientes — esta integración no se pudo verificar contra la documentación oficial completa de Mercado Pago al construirla.
🔒 Seguridad de inventario

Si lo configuras, se va a pedir este NIP antes de agregar, editar o eliminar productos, y antes de agregar stock escaneando — para que el personal de venta no pueda tocar el inventario sin permiso. Déjalo vacío para no pedir nada (como hasta ahora).
